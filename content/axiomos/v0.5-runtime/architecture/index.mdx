The architecture section describes the implemented system on the unmerged `feat/v0.5-runtime` branch: subsystem boundaries, invariants, control flow, ownership and trust relationships. The branch adds an opt-in **managed runtime** (`managed-runtime` feature) for uploading, preparing, handing off and rolling back one signed 100 Hz controller; it is documented in its own [Managed Runtime](/axiomos/v0.5-runtime/runtime) section, and the pages here describe where it touches the existing kernel. The canonical v0.5 contract is [docs/plans/active/v0.5-bounded-runtime-evolution.md](https://github.com/pro-utkarshM/axiomOS/blob/feat/v0.5-runtime/docs/plans/active/v0.5-bounded-runtime-evolution.md).

## Authority order

When documents disagree, the repository resolves them in this order ([system-overview.md](https://github.com/pro-utkarshM/axiomOS/blob/feat/v0.5-runtime/docs/architecture/system-overview.md)):

1. Generated authorities under `docs/reference/generated` (ABI, targets, components, artifacts, build inputs, quality).
2. Accepted decisions under `docs/decisions`.
3. Current architecture documents.
4. Source code and its required gate evidence.
5. Archived and legacy documents (historical only).
