Every first-party Rust `unsafe` syntax site is an owned review obligation. `ledger.toml` is the maintained catalog (path rules, owners, invariants); `ledger.md` is generated from it plus the current source by `python3 scripts/verify/unsafe-ledger.py --write`. Review and CI run `cargo xtask check unsafe`; `--list` prints a per-site TSV (location, construct, owner, invariant, callers, tests, priority, review date).

## Snapshot

The branch refreshes the ledger for the managed runtime (`662cd4f`, "refresh unsafe inventory hash", and earlier inventory updates). Net change: 42 more sites in 4 more files, mainly managed map updates, the IRQ-masked allocator, firmware MMIO adapters (FIRMWARE-MMIO grows from 1 to 12) and managed execution.


**736 sites in 125 files** on this branch (694 in 121 on `main`): 153 attributes, 465 blocks, 25 externs, 69 functions, 23 impls, 1 trait. Counts are syntactic source sites (including tests and fuzz targets, excluding build output and corpora), not expanded macro instances and not a proof of soundness. The inventory is fingerprinted (`sha256:be108a3a...`) so drift is detected.

## Review policy

- **P0** gates release until the premises are enforced in code and exercised through a fault or concurrency path. **P1** needs targeted tests before the subsystem is complete. **P2** is platform/ABI glue with documented external premises. **P3** is test/tooling only.
- The path rule is the durable owner; a new path containing `unsafe` fails `--check` until classified, and any count drift fails `--check`.
- "Boot smoke" is integration evidence, not a substitute for provenance, aliasing, lifetime, mapping, interrupt, DMA or MMIO tests. Rows that say coverage is missing remain open audit debt.
- Contributor rule: every `unsafe` block needs a `SAFETY:` comment.
