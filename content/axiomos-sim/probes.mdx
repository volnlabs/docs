## Phase 1 risk gate (2026-07-30)

Goal: prove axiomOS reaches UART on a stock Renode ARMv8-A platform before any custom Pi modeling.

- Renode `1.16.1.16973`, stock `platforms/cpus/cortex-a78.repl` (UART `0x09000000`, GIC `0x08000000`, RAM `0x40000000`), DTB `renode/probes/minimal-virt-stub.dtb` loaded at `0x44000000`, ELF entry `0x40080000`.
- `tools/probe-armv8a.sh` runs 0.1 virtual seconds under a 90 s wall timeout and requires both exit 0 and the marker `Logging initialized` (Renode 1.16 can exit 0 after Monitor errors).
- Result: marker at about 1.0 ms virtual time; continued through exception vectors, physical memory, page tables, and heap init. Not a userspace claim.
- Observations: early writes target the Pi UART `0x10_7d00_1000` (absent on that platform); post-heap high-half accesses were unmapped there, motivating Phase 2 board work.

Decision: proceed to Phase 2; the "revisit backend choice" stop condition was not triggered.

## Phase 2 `virt-pi5` boot (2026-07-30)

Gate: the unmodified `embedded-rpi5` image must print `=== axiomos eBPF init ===` on `virt-pi5`.

- The initial run entered at Renode's default EL3. axiomOS treats non-EL2 entry as EL1, so it programmed EL1 MMU registers while still at EL3, and high-half accesses went untranslated to the bus.
- Fix: `cpu SetAvailableExceptionLevels false false` and `gic DisabledSecurity true`, plus PL011 handoff state. High-half warnings vanished; real MMU translation is exercised, with no Renode fork or address alias.
- Current result:

```text
PI5_BENCH_FAIL stage=rp1_irq_route error=PcieLinkDown(0)
kernel panicked ... memory allocation of 20971520 bytes failed
```

The first line is expected until a PCIe/RP1 model exists. The second is the userspace blocker: the 20 MiB embedded rootfs allocation exceeds the guest heap's usable contiguous capacity, an axiomOS issue.

## Later evidence (branch only)

These probes exist on `fix/adapter-pid-readiness`, not `main`:

- **Identified virt build (2026-09-30):** a clean clone of axiomOS `b8953b5` with `nightly-2026-07-02` built the 20 MiB rootfs, but the `virt,cloud-profile` kernel failed to link because `kernel/linker-virt.ld` omits `__kernel_end`.
- **Linker fix (2026-09-30):** axiomOS PR #196 (commit `a6f48d1`) fixed the symbol and a validated manifest bundle was produced. Three QEMU runs (`virt-11.1,gic-version=2,virtualization=off,secure=off`, Cortex-A57, 1 GiB, semihosting off) each timed out after 30 s with empty UART. GDB showed `_start_asm` at `0x40080000` with `x0=0` storing to the Pi UART `0x107d001000`, after which PC jumps to `0x200`. The blocker is the Pi-specific early UART store on the virt entry path.
- **Renode model audit and RP1 models (2026-10-01):** see [RP1 Models](/axiomos-sim/backends/rp1-models).
